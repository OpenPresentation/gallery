# Changelog

## Unreleased

- Gallery 2.0.0 validates and builds with immutable merged v2 engine sources for this release only, preserving all release gates and dependency-free published files. Layout records retain usage descriptions and their published SVG preview links.

- **2.0.0, a major release: the layouts changed, and there is no migration path.** The 278 layouts of 1.x (OPF 0.18 placeholder records, `opf-layout/v1`) are removed, with no alias, and replaced by the 28 layouts of OPF 0.19, named by intent and written as grid templates (`opf-layout/v2`: `areas`, `columns`, `rows` and `regions` that say which content each region accepts and how several blocks flow in it), in six groups: openers and closers `cover`, `section`, `agenda`, `statement`, `closing`; text `text`, `list`, `quote`, `two-column`; groups of items `pillars`, `comparison`, `process`, `timeline`, `faq`; numbers `metrics`, `scorecard`; visuals `image`, `image-beside`, `gallery`, `chart`, `chart-beside`, `table`, `table-beside`, `code`; mixed `hero`, `dashboard`, `team`, `logos`. Six 1.x ids are also 2.0.0 layouts and now name the new template: `agenda`, `comparison`, `dashboard`, `faq`, `timeline` and `two-column`. Any other 1.x id no longer resolves: a deck that names one gets `opf/unresolved-reference` and its slides compose automatically, unless it embeds the old record. The variants the old ids encoded (boxed, vertical, title and content alignment, crop or fit, item images) are design settings, not layouts. `CATALOG_SCHEMA` is `2` (`opf.catalogSchema` in `package.json`), and the records need `@openpresentation/opf` 0.19 or later. The layouts are written in this repository from now on; the other kinds are unchanged. `@openpresentation/gallery/previews` now holds one SVG preview per layout, keyed by its id and drawn by the pinned `@openpresentation/opf-render` (`npm run previews`, checked by `npm run check:previews`), instead of the 70 HTML slide-archetype thumbnails. The pixel-stability check treats 2.0.0 as a new baseline (a `CATALOG_SCHEMA` change needs a major release) and draws each template with every region filled and with every region empty; layout index entries carry `summary` and `group`.
## 1.0.0 (2026-10-10)

Released from `3458f50`; the original tagged changelog kept this entry under Unreleased.

- First release of `@openpresentation/gallery` from OpenPresentation/gallery: the pptx.gallery catalog on its own version line. `import { gallery } from "@openpresentation/gallery"` and register it with `catalogs: [gallery]`. It holds the records that `@openpresentation/opf/catalog`'s `defaultCatalog` held up to OPF 0.18: 278 layouts, 4 themes, 14 colour schemes, 89 font schemes, 48 narratives, 16 audiences, 9 purposes and 7 tones. The package also exports `GALLERY_SOURCE`, `CATALOG_SCHEMA` (`1`, also `opf.catalogSchema` in `package.json`), `catalogDisplay`, `catalogIndexes` and `catalogManifest`; `@openpresentation/gallery/previews` exports the layout previews. It has no dependency, not even for its types: `GalleryCatalog` has the shape of core's `Catalog`. New records are a minor release; a removed or renamed id or a changed drawing is a major release, which CI enforces by drawing every existing layout, theme, colour scheme and font scheme against the previous published release. Replaces the 0.0.1 placeholder.
